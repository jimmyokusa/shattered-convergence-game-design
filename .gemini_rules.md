# ⚙️ Core Repository Rules & Development Directives

> **PRIMARY OPERATIONAL RULE:** This repository operates under strict **Build-First Discipline**. Creative design work is frozen until engine implementation milestones are achieved.

---

## 🚫 Binding Development Rules for AI Agents & Assistant Sessions

1. **Strict Scope Lock (No Scope Expansion):**
   * **DO NOT** invent, suggest, or generate documentation for new characters, moves, signature mechanics, fighting stages, or game modes.
   * Any request that would expand scope must be answered with a reference to [`VERTICAL_SLICE.md`](VERTICAL_SLICE.md) and a polite refusal.

2. **No Unearned Design Documentation:**
   * **DO NOT** write or revise design documentation for Tier 2 or Tier 3 characters while Tier 1 is still in development.
   * Milestone 0 ([`VERTICAL_SLICE.md`](VERTICAL_SLICE.md)) must be 100% playable in Unity before any Tier 2/3 work resumes.

3. **Frame Data Rules:**
   * **DO NOT** author, adjust, or "improve" numerical frame data values in Markdown files.
   * Frame data is an empirical result discovered in the engine through playtesting in the UFE Move Editor, not a document specification. Docs only transcribe engine values *after* they are tuned.

4. **UFE Capability Claims:**
   * Whenever asserting what UFE 2 can or cannot do natively, you **MUST** tag the assertion with `[VERIFY]` if it has not been verified in the running Unity engine.

5. **Single-Developer Constraint:**
   * Every process, specification, and workflow must assume a **team size of ONE**. Never suggest pipelines requiring dedicated animators, concept artists, or audio teams.

6. **Mandatory Unity Log Verification:**
   * **ALWAYS** inspect `unity/Logs/Editor.log` immediately after creating, updating, or generating any Unity C# scripts or asset configs. Never declare a C# script or builder tool complete until log extraction confirms zero compilation errors or unhandled exceptions.
